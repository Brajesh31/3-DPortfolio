# Accessibility

Accessibility is an ongoing quality goal for this portfolio. This document describes practical expectations for reviewing and improving the existing interface. It is not a claim of certified WCAG conformance.

## Review targets

Use WCAG 2.2 Level AA as a reference target where applicable.

- All interactive controls should be reachable and operable by keyboard.
- Focus must remain visible and follow a logical order.
- Text and meaningful interface elements should have sufficient contrast.
- Images conveying information should have useful alternative text; decorative images should not create redundant announcements.
- Forms should have programmatic labels, clear required-field indicators, and understandable error or success messages.
- Headings and landmarks should communicate page structure.
- Avoid using colour as the only way to communicate state.
- Motion should not be essential to understanding content. Provide a reduced-motion-friendly experience where feasible.
- 3D content should not prevent access to the portfolio's essential information and navigation.

## Manual checks

1. Navigate the site using only Tab, Shift+Tab, Enter, Space, and Escape.
2. Check focus visibility and order on desktop and mobile layouts.
3. Inspect key pages with a screen reader.
4. Zoom to 200% and check for clipped content or loss of functionality.
5. Review text, controls, and focus contrast.
6. Enable the operating system's reduced-motion preference and inspect animated sections.
7. Test the contact form labels and status feedback.

## Reporting an issue

Use the Accessibility issue template and include the page, browser, assistive technology if applicable, reproduction steps, expected result, and actual result. Do not include personal or sensitive information.
